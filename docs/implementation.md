# 実装メモ

現在の実装の技術リファレンス。操作仕様は[操作ガイド](manual.md)を参照。

## 構成

Vite + TypeScript。編集ガイドはDOM/SVG、作品の描画はWebGL2 + GLSL。外部の描画ライブラリに依存しない。

| ファイル | 役割 |
| --- | --- |
| `src/model.ts` | 作品状態（DocumentState）、ストローク、履歴 |
| `src/geometry.ts` | 5種のスプライン評価、幅補間、弧長サンプリング、ランダム倍率 |
| `src/ribbon-mesh.ts` | 曲線サンプル→帯メッシュ変換、採取座標の割り当て |
| `src/color-interpolation.ts` | Bの色補間GLSL（sRGB/OKLab/OKLCH/色相回転） |
| `src/renderer.ts` | GLSL本体、GPUターゲット管理、描画、PNG出力 |
| `src/render-queue.ts` | 世代番号によるキャンセル可能な描画ジョブの直列化 |
| `src/gestures.ts` | 連続操作を1つのUndoエントリにまとめるジェスチャ管理 |
| `src/ui-template.ts` | 静的なエディタHTML |
| `src/main.ts` / `src/style.css` | 編集UI、表示、入力処理 |
| `tests/` | 数学・状態のユニットテストと実ブラウザ検証 |

点・基本幅・採取線の長さは元画像座標のpxで保持し、出力時に作品全体を等比スケールする。表示用の縮小画像への置き換えは行わず、選択した出力解像度で計算した結果をそのまま表示する。

## 状態と履歴

- `DocumentState` に mode（A/B）・kind（スプライン種類）・strokes・mix（Bの色補間）・options（オプション）・background・longEdge を保持する。すべて作品全体の設定で、履歴・描画スナップショット・エクスポートに含まれる。
- Aの採取設定はStrokeに、Bの採取設定は各Pointに保持する。新しい点は作成時のA設定から角度・長さをコピーし、以後独立。A/B切り替えで失われない。
- 履歴は `structuredClone` による全状態スナップショット、最大80件。スライダー・ドラッグ・角度ホイールの連続操作は `gestures.ts` がキー付きジェスチャとして1エントリにまとめ、値が変わらない操作はエントリを作らない。あらゆるプッシュが「空白ダブルクリックによる追加キャンセル」の権利を無効化する。空白部分のダブルクリック（点の追加→即削除）は追加時のエントリごと巻き戻す。
- 編集要求は `render-queue.ts` の世代番号で管理する。編集のたびに世代が進み、進行中の古い計算はストローク境界で中断・破棄される。GPU完了時に最新世代の結果だけを表示に採用し、画像差し替えは `whenIdle()` で実行中ジョブの終了を待ってから資源を解放する。

## 描画パイプライン

### GPUターゲット

写真・作業・完了の3枚のRGBA8ターゲットを使う。作業と完了は役割を交互に入れ替えるダブルバッファで、進行中の計算が完了画像を壊さない。完了側はミップマップを持ち、縮小表示はトライリニア補間になる。エクスポートはミップマップを介さずレベル0を読み出す。

これとは別に、操作中プレビュー専用の作業・完了ペアを持つ（下記「インタラクティブプレビュー」）。写真テクスチャは出力解像度の1枚を両者で共有し、プレビューのために再アップロードしない。

論理的な上方向はテクスチャv=0に統一し、Y反転は画面表示のコピー時だけ行う。

画像読み込み時は2Dキャンバス（sRGB指定）で背景合成と出力解像度へのリサイズを行い、テクスチャへ転送する。以後、ストローク処理中にCPUで写真の画素を操作しない。

### メッシュ

曲線は元画像距離基準の弧長等間隔でサンプリングし、入力イベントの密度やズームに依存しない。頂点は「中心座標・単位法線・採取A座標・採取B座標・（断面位置, 区間進行度）・（符号付き半幅, 帯全体の累積弧長）」を持ち、最終頂点位置はvertex shaderで合成する。この構造により、オプションの変形（後述）はメッシュを作り直さずに効く。累積弧長は区間ごとではなく帯全体の値で、帯座標系の質感（筆の質感）が色区間や進行キーの継ぎ目で再開始しない。

Bでは、曲線サンプルが色の区間境界（点と点の境目）をまたぐ場合にメッシュを分割し、隣接区間の接合部で厳密に同じ採取色を使う。連続する同位置の点は最後の点を代表とし、その幅と採取設定を使う。B-splineの採取色はGreville位置に対応する曲線上へ配置する。

頂点は必要数のFloat32Arrayを一度だけ確保して直接書き込む。GPUバッファは必要時だけ倍々に拡張し、通常は既存領域への書き込みで済ませる。シェーダー・ブレンド・採取写真などの共通設定は1回の描画パスで1度だけ行う。

### 合成と同期

表示中の線を奥から順に、通常のアルファ合成で作業ターゲットへ描く。各線の採取元は常に元写真で、他の線の描画結果を再採取しない。帯の輪郭はスクリーン空間微分（fwidth）によるアルファフェードでアンチエイリアスする。

長い処理は約8msごとにブラウザへ制御を返す。GPU完了待ちとPNG読み戻しはfence／pixel pack bufferで行い、UIをブロックしない。画素の読み戻しはエクスポート時だけ。

WebGLのエラーは蓄積式のため、ターゲット確保の前に残留エラーを消費し、その確保で発生したエラーだけを判定に使う。コンテキスト喪失時は編集を止めて復旧を待ち、復旧後にレンダラーを作り直して再計算する。

### インタラクティブプレビュー

点・経路のドラッグ、スライダーのinput、角度スクロールの最中は、出力解像度の代わりに画面サイズ相当の長辺（下限800px・上限2048px）で描画する。プレビューが使われるのは、その長辺が出力長辺の80%以下になるときだけ。判定は `previewLongEdge()`（model.ts）にある。

- メッシュのサンプリング間隔・オプションの係数換算はプレビュー解像度のスケールで計算され、シェーダーは同一。頂点数も解像度に比例して減る。
- 操作の終了イベント（pointerup、スライダーのchange/blur）で即座に、終了イベントのない操作（角度スクロール）はプレビュー完了から約250msのアイドルで、出力解像度の再計算を要求する。
- プレビュー表示中はエクスポートを無効化する。エクスポートは常に出力解像度側の完了ターゲットを読み、レンダラー側でも出力解像度の描画が完了するまで書き出しを拒否する。OFF時とのバイト一致保証は出力解像度の描画にだけ関わり、プレビューの影響を受けない。
- 単発の編集（点の追加・削除、モード切り替え、チェックボックス等）はプレビューを介さず出力解像度で描く。

## A/B/Cと色補間

- **A**：始点の採取線1本の色の並びを帯全体に使う。fragment shaderは元写真を1回参照する。
- **B**：各頂点に隣接2点の採取座標と区間進行度を渡し、fragment shaderで元写真を2回参照して補間する。正規化した帯幅の左端同士・中央同士・右端同士が対応するクロスフェードで、筋を横へ移動させる変形ではない。
- **C**：Strokeが持つ直線の採取経路 Q（始点・終点）と区分線形の進行キー f（帯の弧長比 s → 経路の弧長比 q）から、断面ごとの採取中心を `Q(f(s))` で決める。断面の採取線は固定の角度・長さで、経路の接線には追従しない（速さの編集と回転の混同を避けるため）。頂点の採取座標はメッシュ生成時にCPUで計算し、fragmentは元写真を1回参照するだけ——シェーダはAと同じ経路を通る。進行キーの位置でメッシュを分割し、各クアッド内で採取座標が線形に保たれる（停止・逆走の折り目が補間で滲まない）。s は入力イベントや制御点の間隔ではなく弧長から求める。

補間方式は `color-interpolation.ts` のGLSLに分離し、`mixMode` ユニフォームで選択する。切り替えでシェーダーを再コンパイルしない。

- 区間の補間量は全方式共通で `smoothstep(0,1,t)`。点の前後の変化を穏やかにする。
- OKLab系はsRGB→linear→OKLabの変換・逆変換をGLSLで行い、結果を0〜1にclampして符号化sRGBへ戻す。
- OKLCHの無彩色（彩度≈0）は色相が不定になるため相手側の色相を借りる（`atan(0,0)` 未定義対策）。
- 色相回転は近回り経路に**整数回転**（±2πの倍数）だけを追加する。任意角度を足すと区間終端の色が採取色からずれ、区間の継ぎ目の色一致が壊れるため、回転数に限定した。

写真外の採取は端の色を延長（clamp）する。帯の自己交差は描画順に上書きされ、描いた色を再採取しない。

## オプション

`DocumentState.options` に保持し、UIの設定行はチェックONのときだけ表示する。OFF時は全係数が0で、出力は無効時とバイト一致になる。

- **写真で帯を変形**（選択式・調整値はアルゴリズムごとに保持）：vertex shaderで採取写真を参照する。輝度ディスプレイスメントは法線方向への押し出し（短辺比％を出力pxへ換算）。エッジ幅変調は±3px（元画像換算）の輝度差分によるエッジ強度で幅係数を0〜3倍に変える。有効なのは選択中の1つだけ。
- **フェイク3D**：fragment shaderで断面位置から円筒状の擬似法線を作り、拡散＋鏡面ライティングを乗せる。光源方向は固定。
- **筆の質感**（実験・選択式・強さはモードごとに保持）：写真の採取とは独立に、帯座標（進行方向の累積弧長 s, 断面の符号付き距離 v。ともに元画像px換算）で毛筋状のノイズ場を生成し、4方式で使う。固定seedと毛筋の間隔（元画像px、画像差し替え時に等比スケール・2〜48にクランプ）を設定に保持し、出力解像度を変えても毛筋の本数は変わらない。
  - *習字のかすれ*：ノイズのしきい値処理で被覆マスクを作りアルファへ掛ける。帯の両側ほど欠けやすく、切れ目の周囲は半透明の掠れになる。
  - *油絵の凹凸*：ノイズを高さ場とみなし、有限差分の勾配から擬似法線を作って固定光源でライティングする。平坦部が採取色と厳密に一致するよう正規化してあり、フェイク3Dとの併用は二重照明になるため実験時は使い分ける。
  - *エッジ強調*：縁までの距離（元画像px、細い帯では半幅の40%に制限）で両縁に暗いリム、光源側に細いハイライトを乗せる。中央は変更しない。
  - *複合*：かすれの被覆と凹凸の高さを連動させ、絵の具が無い場所には凹凸も出さない。

## 容量と限界

- 長辺5000pxの例（5000×3438）では、写真＋ミップ付きの作業・完了の3枚で約252MB（十進表記）。表示バッファ、元画像、メッシュ、PNG出力時のCPUコピーが別途必要。プレビューのペアは最大でも長辺2048pxの2枚（ミップ付き約31MB）で、最初のプレビュー描画まで確保しない。
- 端末の上限は `MAX_TEXTURE_SIZE` と `MAX_VIEWPORT_DIMS` の小さい方。超過や確保失敗はエラーを表示し、解像度を勝手に下げない。
- パン・ズーム・画面リサイズでは、同じ編集世代・同じ選択線の中心線サンプルを再利用し、曲線を再計算しない。

## テスト

```sh
npm test              # ユニットテスト
npm run build         # 型検査＋本番ビルド
npm run test:browser  # dev server起動とChromeが必要
```

- `tests/*.test.ts`（ユニット）：5種の曲線の端点・有界な幅・重複点の縮退、TCBゼロ調整とCatmull–Romの一致、幅補間の非オーバーシュート、履歴（undo/redo/破棄）、出力サイズの縦横比、メッシュの頂点属性（中心・単位法線・符号付き半幅）、B-spline採取のGreville対応、区間分割、角度によるランダム倍率、初期幅。
- `tests/browser.spec.ts`（実ブラウザ）：編集・履歴・カーソル中心ズーム、GPU画素比較（各点の色の再現、色補間方式ごとの中間色の理論値照合、途中の画素を拾わないこと）、複数線の合成順と表示切り替え、5000px出力の寸法とA/B切り替え往復のバイト一致、JPEGの向き、透明PNGの背景合成、GPUリソースの再利用回数、コンテキスト喪失からの復旧、オプションと色補間のON/OFFでベースラインとバイト一致、操作中プレビューの表示・エクスポート禁止・出力解像度への復帰。

ユーザーの写真はテストにもGitにも含めない。検証は生成パターン、透明PNG、EXIFの向きを埋めたJPEGで行う。
